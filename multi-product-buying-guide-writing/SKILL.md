# 多产品导购爆款写作

## 风格使用边界

这个 Skill 只提供多产品导购结构和消费决策表达，不用于扮演或复刻某个真实创作者。

不要复制创作者的具体人设、固定私人口头禅、个人经历或高度可识别的句式指纹。如果用户要求“完全模仿”某个真实账号，改成更安全的版本：同类型多产品导购结构 + 清楚的取舍判断 + 原创表达。

## Core Intent

Write like a practical buying-decision assistant, not a neutral spec sheet.

The target reader is not asking "what happened?" They are asking:

- Should I buy now?
- Which one fits my budget?
- Which one will not feel outdated soon?
- What is the catch?
- Can I copy the answer directly?

Output must reduce decision anxiety. Favor clear recommendations, visible tradeoffs, and audience segmentation.

## When To Verify Data

If the article mentions current prices, stock, subsidies, rankings, sales volume, release status, specs, benchmark scores, battery tests, or software policies, verify with current sources before writing. Do not invent:

- reference prices
- "zero negative review" claims
- ranking positions
- launch dates
- configuration options
- sales numbers
- subsidy amounts

If verification is not possible, write with uncertainty markers: "目前公开信息显示", "电商参考价约", "以实际页面为准", "网传信息仍需等发布会确认".

## Article Positioning

Default positioning:

- 导购型: Help the reader choose.
- 陪伴型: Speak like a familiar, honest helper.
- 决策型: End with a concrete "who should pick what".

Avoid:

- pure parameter dumping
- all-positive praise
- vague "depends on personal preference" endings
- pretending first-hand testing if only doing information synthesis
- overusing sensational claims without proof

## High-Click Topic Angles

Prefer one of these angles:

- Budget: "1000元档", "2000元档", "3000元档", "5000元预算".
- Timing: "618", "双十二", "国补后", "清仓期", "涨价潮前", "新机发布后".
- Anxiety: "怕买贵", "怕踩雷", "怕用两年就卡", "怕续航崩", "怕信号差".
- Persona: "小屏党", "游戏党", "拍照党", "打工人", "学生党", "外卖员", "女生".
- Decision conflict: "A 和 B 怎么选", "老旗舰还是新中端", "iPhone 稳还是安卓卷".
- Proof wrapper: "酷安热榜", "安兔兔榜单", "销量榜", "续航测试", "用户口碑".

## Title Formula

Build titles from 4-5 parts:

`time/event + price/spec + count/object + emotional hook + outcome promise`

Useful title ingredients:

- Time/event: "2026年", "5月", "618", "国补后", "涨价潮下", "清仓倒计时".
- Price/spec: "2000元档", "3000元以内", "16+512GB", "1TB", "7000mAh".
- Count/object: "3款手机", "5款旗舰", "四大机型", "这几台".
- Hook: "真香", "闭眼入", "捡漏", "价格跳水", "清仓", "零差评", "杀疯了".
- Promise: "用五年不卡", "看完不纠结", "不踩雷", "一步到位".

Examples:

- `2026年3000元档真香机盘点：这3款16+512GB，闭眼入不踩雷`
- `618捡漏别乱冲：4款降价旗舰怎么选，看完不纠结`
- `小屏党换机指南：这5款手感、续航、拍照都在线`

Title constraints:

- Use concrete numbers whenever possible.
- Avoid title promises that the article cannot substantiate.
- Prefer one main anxiety per title.

## Opening Formula

Open with warmth, then pain, then promise.

Template:

```text
大家好呀，我是[账号名/作者名]。

最近很多人都在纠结[场景/节点]：预算就这么多，又想要[需求1]、[需求2]、[需求3]，还怕[风险]。

所以今天不绕弯子，直接按[预算/人群/场景]筛出[数量]款更值得看的机型。每一款都会说清楚亮点、短板和适合谁，准备换机的朋友可以直接抄作业。
```

If the user wants a more personal tone, add:

```text
先声明一句，我这里不做无脑吹。好在哪里会说，短板在哪里也会说，毕竟买手机不是看参数热闹，最后还是要自己用着舒服。
```

## Body Structure

For list/recommendation articles, use this structure:

1. Short context: why this topic matters now.
2. Selection criteria: budget, storage, battery, chip, screen, camera, signal, hand feel, system.
3. Repeated product blocks.
4. Quick decision summary.
5. Comment prompt.

Product block template:

```text
### 1. [Model Name]: [one-line positioning]

参考价/参考配置：[price/config, if verified]

这款机型最大的亮点是[main advantage]。如果你在意[scenario], 它的[feature]会比较有感知。

具体来看，[performance/battery/screen/camera/system/hand feel]分别如何。不要只堆参数，要说明这些配置对日常使用意味着什么。

短板也要说清楚：[drawback]. 所以它更适合[persona], 不太适合[persona].
```

Keep each block balanced:

- 1 core selling point
- 2-3 supporting details
- 1 honest shortcoming
- 1 clear audience recommendation

## Decision Summary

End with a fast "copy homework" section:

```text
最后简单总结：

重性能和游戏，优先看 A。
重拍照和人像，优先看 B。
想要大电池、少充电，C 更稳。
预算卡得比较死，D 的性价比更高。

如果是你，这几款里会选哪一台？评论区聊聊。
```

Never end with only "各有优缺点". Give the reader a usable sorting rule.

## Language Style

Use conversational Chinese with high information density.

Good phrases:

- "不绕弯子"
- "直接抄作业"
- "短板也很明确"
- "不是它的主场"
- "核心取舍在于"
- "适合谁、不适合谁"
- "看完基本就不纠结了"
- "预算有限但想一步到位"

Traffic phrases, use sparingly:

- "闭眼入"
- "真香"
- "捡漏"
- "价格跳水"
- "清仓"
- "杀疯了"
- "卷王"
- "续航怪兽"
- "拍照神机"

Avoid:

- "遥遥领先" unless sourced or clearly opinionated
- "无敌", "吊打", "唯一选择" unless intentionally writing strong opinion content
- too many exclamation marks
- repeating the same hook phrase in every paragraph

## Trust-Building Moves

Add credibility by doing these:

- Mention selection criteria before recommendations.
- Say both advantages and disadvantages.
- Use "参考价" instead of absolute price when prices fluctuate.
- Distinguish verified facts from personal judgment.
- Avoid saying "实测" unless actual test data is provided.
- When using rankings, name the ranking source and date.

Useful disclaimer style:

```text
价格和活动会随平台变化，本文只按当前能查到的参考价和公开配置来聊，实际下单前还是建议再看一眼店铺页面。
```

## Optimization Over The Original Corpus

Improve beyond the original pattern in these ways:

- Reduce duplicated opening boilerplate when writing multiple articles.
- Add a visible selection standard so recommendations feel less arbitrary.
- Make title claims match body evidence.
- Use clearer decision tables when comparing more than 3 products.
- Separate "verified specs" from "subjective recommendation".
- Put the shortcoming closer to the recommendation, not hidden at the end.
- Avoid recycling the same "用五年不卡" promise unless backed by chip, storage, update policy, and use-case assumptions.

## Optional Comparison Table

For 3+ products, add a compact table before or after product blocks:

```markdown
| 机型 | 更适合谁 | 核心亮点 | 主要短板 |
|---|---|---|---|
| A | 游戏党 | 性能/散热强 | 影像一般 |
| B | 拍照党 | 主摄/长焦强 | 价格更高 |
| C | 续航党 | 电池大 | 机身偏重 |
```

Use tables for decision clarity, not as a replacement for explanation.

## Quality Checklist

Before finalizing, check:

- Does the title contain a concrete audience, price/spec, or decision promise?
- Does the opening identify the reader's anxiety within the first 3 paragraphs?
- Does each recommendation include a drawback?
- Does the article answer "who should buy this?"
- Are current prices/specs/rankings verified or clearly caveated?
- Is there a quick final sorting rule?
- Is the comment prompt specific enough to invite replies?

## One-Shot Article Skeleton

```markdown
# [Title]

大家好呀，我是[Name]。

[Time/event]一到，很多人又开始纠结[main decision]. 预算有限，但又想要[need 1]、[need 2]、[need 3]，确实很容易看花眼。

今天就按[selection angle]筛出[数量]款更值得看的机型。标准很简单：[criteria]. 好在哪里会说，短板在哪里也会说，准备换机可以直接抄作业。

| 机型 | 适合人群 | 核心亮点 | 主要短板 |
|---|---|---|---|
| [A] | [persona] | [selling point] | [drawback] |

## 1. [A]: [positioning]

参考价/配置：[verified or caveated info]

[Explain main advantage in daily-use language.]

[Explain 2-3 supporting specs and their actual experience impact.]

短板也很明确：[drawback]. 所以它更适合[persona], 如果你特别在意[concern], 就要谨慎。

## 2. [B]: [positioning]

[Same structure.]

## 3. [C]: [positioning]

[Same structure.]

## 怎么选

重[need 1]，优先看[A]。
重[need 2]，优先看[B]。
预算更紧，优先看[C]。

如果是你，这几款里会选哪台？评论区聊聊。
```
