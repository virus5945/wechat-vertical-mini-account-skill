# 示例输出

## 示例 1：资料较完整的多产品推荐

用户输入：

```text
使用 multi-product-buying-guide-writing。
预算 3000 元以内，目标读者是大学生。候选机型：A、B、C、D。
已核对信息：A 参考价 2499，主打性能；B 参考价 2799，主打拍照；C 参考价 2299，主打续航；D 参考价 2999，主打轻薄。
```

推荐输出：

```markdown
# 3000 元以内学生党换机：这 4 款怎么选，看这张表就够了

先说结论：预算 3000 元以内，学生党换手机不要只看跑分，也别只盯拍照。更实际的判断是：你每天用手机最多的场景是什么。

| 机型 | 更适合谁 | 核心亮点 | 主要短板 |
|---|---|---|---|
| A | 游戏党 | 性能强，适合高负载场景 | 影像不是主场 |
| B | 拍照党 | 主摄和人像更稳 | 价格更高 |
| C | 续航党 | 电池更耐用 | 机身可能偏厚 |
| D | 轻薄党 | 手感好，通勤舒服 | 性价比不如前三款 |

## 1. A：更适合游戏和高性能需求

A 最大的优势是性能。对学生党来说，如果你经常打游戏、剪短视频、同时开很多应用，它的优势会更明显。

短板也很清楚：拍照不是它的主场。如果你更在意人像、夜景和旅行拍摄，A 不一定是最优先。

## 2. B：更适合喜欢拍照的人

B 的核心卖点是影像。它更适合经常拍人、拍校园生活、拍旅行记录的用户。

但它价格更接近预算上限，如果你只是日常扫码、上课、刷视频，没必要为了影像多花这部分预算。

## 怎么选

重游戏和性能，优先看 A。  
重拍照和记录生活，优先看 B。  
想省心续航，优先看 C。  
想要轻薄手感，优先看 D。

价格和活动会变化，下单前建议再核对店铺页面和售后政策。
```

## 示例 2：资料不足时的安全输出

用户输入：

```text
使用 multi-product-buying-guide-writing。
写一篇 2000 元档 5 款手机推荐，我还没整理价格和配置。
```

推荐输出：

```markdown
我先按“2000 元档普通用户换机”来搭文章框架。因为你还没给具体机型、价格和配置，下面不会编造参数，只给可替换模板。

## 标题方向

1. 2000 元档手机怎么选：别只看处理器，先看这 5 个取舍
2. 预算 2000 左右换手机，这几类人最容易买错
3. 2000 元档换机清单：性能、续航、拍照到底怎么排优先级

## 选机标准

| 维度 | 为什么重要 | 需要补充的信息 |
|---|---|---|
| 性能 | 决定游戏、剪辑和长期流畅度 | 芯片、内存、散热 |
| 续航 | 决定一天是否够用 | 电池、充电功率、重量 |
| 屏幕 | 决定长时间使用体验 | 分辨率、刷新率、护眼方案 |
| 影像 | 决定拍照上限 | 主摄、长焦、防抖 |
| 售后 | 决定长期稳定性 | 品牌、保修、系统更新 |

## 下一步需要你补充

把候选机型、当前参考价、版本和你想推荐的人群发我，我再输出完整正文和对比表。
```
